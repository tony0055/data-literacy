# 데이터 덱: 공통 덱 스킬 위에 얹는 data-literacy 층

덱의 순서와 디자인 기준은 school-projects 공통 [designing-decks-and-motion](../../../.agents/skills/designing-decks-and-motion/SKILL.md)이 소유한다(내용 → 브랜드 → 참고 디자인 시스템 → 표준 문서·확인 화면 → 제작 → 전 장 렌더). 이 문서는 그 각 단계에 **이 수업에서 더하는 것만** 적는다. 분석은 [course-workflow](course-workflow.md)의 단계 1–7을 먼저 끝낸다. 강의 덱에서 가져온 표현 패턴은 [presentation-patterns](../school/school_project/course-domain/presentation-patterns.md).

최신 요청의 형식·장수·시간이 우선한다. 기존 덱을 소급 수정하지 않는다.

## 기본 납품

`school/school_project/weekN/<project>/` 안에 분석 산출물(`report.md`, `claims.csv`, `chart-data.*`)과 `presentation/`(`index.html`, `src/`, `design-standard/`, `design-standard.html`, `assets/`, `renders/`), `speaker-notes.md`, README(입력·출처·실행법·검증·한계). 시간 미지정이면 4–6분, 팀 기말은 계획값 8분+질의 4분(미확정)으로 준비한다.

## 1. 내용 (공통 단계 1에 더할 것)

- 스토리 뼈대는 수업 흐름을 쓴다: **질문 → 데이터(출처·n·기간) → 근거(차트) → 검증(손계산·민감도) → 한계 → 결론/행동**. 실습 발표는 함정 증상 → 명세 개선 → 전후 결과.
- 1장 1메시지, 결론형 헤드라인(한 줄). 장마다 그 장이 답할 질문과 `claims.csv`의 근거 행을 적는다.
- 주장 라벨 = 결론 등급(`기술`·`추정`·`인과`) + 확인 상태(`확인`·`계획안`·`교육용 합성`·`외부 자료`). 라벨은 숫자 옆에 두고 미관 때문에 지우지 않는다.
- 문체 기본값: 슬라이드 글은 개조식(명사 종결, 강의 자료 문체 기준), 대본은 합니다체. 요청·공지가 다르면 그것을 따른다.
- 용어집: 같은 대상은 한 단어(예: "응답자"와 "사용자"를 섞지 않음), 통계 기호는 처음 한 번 풀어서.

## 2–3. 브랜드와 참고 디자인 시스템

- 과제 고유 브랜드가 없으면 주제·청중에 맞춰 공통 브랜드 프로필을 채운다. 다른 프로젝트(쓰담)의 색·서체를 쓰지 않는다.
- 참고 디자인 시스템은 수업 지정 **SEED**다(공통 카탈로그의 SEED 항목). 새로 고르지 않는다. 단일 HTML 덱이므로 SEED 패키지를 의존성으로 설치하지 않는다.
- **토큰 값은 [seed-design.io](https://seed-design.io/) 문서 페이지에서 읽을 수 없다.** 값 칸이 클라이언트에서 그려져 본문 추출에 빈칸으로 나온다(2026-10-03 확인). 값은 같은 조직이 배포하는 **공식 npm 패키지의 CSS**에서 가져온다:
  - `https://cdn.jsdelivr.net/npm/@seed-design/stylesheet@<버전>/global.css` (Apache-2.0). 라이트 테마 블록의 `--seed-scale-color-*`·`--seed-semantic-color-*`를 쓴다.
  - `@seed-design/design-token` 패키지에는 **이름만** 있고 값이 없다. 값 출처로 쓰지 않는다.
  - 받은 파일을 `<deck>/design-standard/`에 스냅샷으로 보관하고 버전·URL·받은 날짜·해시를 `domain.md`에 적는다.
- 문서 페이지는 **구조와 의미**(역할 기반 색 체계, 접근성 기준, 타이포 토큰 구성, 권장 글꼴 Pretendard)를 확인하는 데 쓰고, 확인한 주소와 날짜를 남긴다.
- 토큰 이름·값을 기억으로 만들지 않는다. 위 경로가 모두 막히면 SEED를 적용했다고 보고하지 않고 막힌 근거를 알린다.
- SEED는 모바일 UI 기준이다. 1920×1080 발표 크기로 키운 글자 프리셋은 공통 표준 값을 따르고 SEED 단계와의 차이를 `typography.md`에 기록한다.

## 4. 표준에 더할 데이터 시각화 토큰

| 역할 | 기준 |
| --- | --- |
| 의미 색 | 강의 덱처럼 색을 교육 장치로 쓴다: 개념·근거(브랜드/중립), 함정·주의(critical 계열), 검증·실습(positive 계열), 미확정·계획(warning 계열). 각 역할은 SEED 토큰에 매핑 |
| 의미 색의 **채움/글자 분리** | SEED 의미 색은 모바일 면·아이콘용이라 **그대로 글자에 쓰면 흰 배경 대비 4.5:1을 넘지 못한다**(2026-10-03 측정: blue-500 3.02, red-600 3.95, green-500 3.28, yellow-400 2.17, gray-600 3.42). 의미마다 채움(접미사 없음) / 글자(`-text`, 더 진한 단계) / 옅은 바탕(`-pale`) 세 토큰으로 나누고, 측정값을 `color.md`에 적는다 |
| SEED primary | `semantic-color-primary`는 carrot 계열이고 당근 브랜드 값이다. 복제하지 않는다. 시스템 강조로 정의된 blue 계열을 근거·강조 역할에 매핑하고 이유를 `domain.md`에 적는다 |
| 차트 색 | 강조 1색 + 중립 회색. 범주는 색 외 모양·위치·직접 라벨로도 구분. 순서 없는 범주에 순서형 컬러맵 금지. 중립 계열이 둘 이상이면 선 종류까지 달리해 서로 구분한다 |
| 차트 가로축 | **가로축이 연도면 실제 연도 간격으로 그린다.** 2013·2022·2023을 등간격으로 두면 9년과 1년이 같은 폭이 된다. 구간 라벨(2007-09 같은 묶음)만 등간격이 맞다 |
| 계열별 기간 | 기간이 다른 계열을 **한 축 라벨 아래 묶지 않는다.** 계열마다 자기 연도 라벨을 갖게 그리고, 기간이 다르다는 사실을 장에 적는다 |
| 값 라벨 자릿수 | 출처 표기의 소수 자릿수를 보존한다(45.0을 45로 줄이지 않는다). 한 차트 안에서 자릿수를 통일한다 |
| 차트 글자 | 축 눈금·범례·직접 라벨은 덱 하한(18px) 이상, 출처·n 캡션만 14–15px |
| 차트 부품 | 제목(결론형) · 축 이름+단위 · n과 기간 · 출처·기준일 · 값 직접 라벨 · 강조 주석(화살표+한 줄) |
| 수식 블록 | 기호를 쓰면 같은 장에 기호 뜻과 실제 값 대입 예를 함께 |

확인 화면(`design-standard.html`)에 차트 부품 한 벌(막대·선·히스토그램·산점도 샘플)과 의미 색 4종을 실제 CSS로 그려 렌더해 본다.

## 5. 제작

### 골격

공통 덱 골격(`src/tokens.css` → `deck.css` → `slides.css`, `<section class="slide">`, `fit.js`, `scripts/render.ts`)을 쓴다. 강의 덱은 reveal.js 다크 테마지만 그 테마·CDN 의존을 복제하지 않는다. 슬라이드 패턴(질문 장, 핵심 박스, 정직/왜곡 대조, 수식 블록, 데모 장, AI 함정 장)은 presentation-patterns의 구조만 빌려 SEED 토큰으로 다시 그린다.

### 차트

- 모든 차트는 `chart-data.json`(검증된 집계)을 읽어 SVG로 그린다. 정적 도해는 강의 방식대로 matplotlib → SVG+PNG(고정 시드, 텍스트 path 변환, 테마 색과 일치)도 된다. 스크린샷 차트를 붙이지 않는다.
- 차트 선택·축·분모 규칙은 [method-selector](../school/school_project/course-domain/method-selector.md)와 course-workflow 단계 7.

### 모션 (데이터 읽기를 돕는 것만)

- 기본 도구는 Anime.js(사용자 지정). 단순 전환은 CSS transition/WAAPI로 충분하면 그걸 쓴다. Manim은 수식·변환 과정 설명이 필요할 때만. 라이브러리는 로컬 번들 또는 HTML 내장, 버전·라이선스 기록.
- 장 안의 빌드 순서: 질문/헤드라인 → 축·기준선 → 데이터(막대 성장·선 그리기·점 stagger) → 강조 1곳 + 주석 → 결론 문장. 한 번에 한 가지가 움직인다.
- 전환 모션: 같은 데이터를 다른 기준으로 볼 때(전체→집단, 평균→분포, 원값→z) 요소가 제자리에서 바뀌게 해 비교를 돕는다.
- 금지: 값·축·분모를 왜곡하는 모션, 끝없이 도는 장식 루프, 3D 원근, 읽기 전에 사라지는 숫자.
- `prefers-reduced-motion`이면 최종 상태를 바로 보여 주고, 장마다 다시 재생 버튼(또는 키)을 둔다. 인쇄·PDF는 최종 상태.
- UI·모션 판단은 `emil-design-eng`·`animate` 스킬 기준을 함께 쓴다.

### 인터랙티브 데모 (설명에 도움이 될 때만)

- 강의 데모 방식: **고정 데이터에 한 변수만** 바꾸는 조작부(슬라이더·버튼) + 전후 수치와 그림을 같이 표시(예: 결측 대치 방식, 이상값 하나 추가, 구간 폭, 축 시작값).
- 입력 이벤트로만 다시 그리고, 슬라이드에 들어올 때 만들고 나갈 때 멈춘다. 빈 draw로 도는 requestAnimationFrame 루프를 만들지 않는다.
- 모의 결과를 실제 검정 결과처럼 표시하지 않는다. PDF/인쇄에는 대표 상태의 실제 수치·정적 그림을 남긴다.

### 생성 에셋

표지·개념 이미지가 꼭 필요할 때만 생성하고(프롬프트·도구·AI 생성 여부 기록), 데이터 차트를 대신하지 않는다. 영상 생성(ego-lite로 Google Flow 접근 등)·유료 생성은 승인 후, 다운로드·재생을 확인한 것만 완성으로 보고한다.

### 발표 제어

방향키/Space 이동, 이전·다음, `Esc` 전체 목록, `S` 또는 버튼으로 발표 노트, 전체화면, 모션 감소·다시 재생, 모바일 가로 화면, 인쇄. 덱에서 분석 보고서와 원자료로 링크한다.

## 6. 검증 (공통 검증에 더할 것)

- 차트의 모든 숫자를 `chart-data`와, `chart-data`의 핵심 값을 손계산/독립 집계와 대조한다(입력 해시 기록).
- 차트를 `chart-data`에서만 그리게 하고(빌드 주입 또는 런타임 읽기), **덱 본문 산문의 수치도 원본 파일과 기계로 대조**한다. 반올림해서 적은 값이 차트 라벨과 어긋나는 일이 자주 생긴다.
- 성별·집단별 값이 함께 있으면 전체값을 역산해 **표 내부 정합성**을 본다(전체 = 남×비중 + 여×(1−비중)). 역산 비중이 연도마다 들쭉날쭉하면 분모 모집단이 바뀐 신호이고, 그 지표의 연도 비교는 쓰지 않는다.
- 모션을 넣었으면 시작·중간·최종 프레임을 **비율로 멈춰 찍고**(`?anim=0 / 0.4 / 1`), 모션 감소 모드와 다시 재생을 확인한다. 최종 프레임의 opacity·변형 값이 실제로 끝 상태인지 숫자로 본다.
- 주장마다 라벨·출처·n이 숫자 가까이에 있는지, 결론 등급을 넘는 동사가 없는지 본다.
- 모션: 시작·중간·최종 상태 스냅샷, 모션 감소 모드, 다시 재생. 데모: 조작 전후 수치가 맞는지.
- 전 장 컨택트시트 + 밀도 높은 장 원본 크기 + 모바일 가로 + 인쇄 미리보기 + 콘솔 오류.

## 7. GitHub Pages 배포 (요청·승인 있을 때만)

발표 링크 제출 과제는 **발표마다 공개 저장소 하나**를 만들어 Pages로 연다(2026-10-12 youth-health부터). 이름은 `tony0055/data-literacy-<주제>`, Pages는 `main` 브랜치 루트다.

- 이 저장소를 통째로 올리지 않는다. 프로젝트 폴더만 별도 디렉터리에 복사해 새 git으로 올린다 — `.DS_Store`·비밀 키·내부 로그 제외.
- 루트에 `presentation/`으로 바로 넘기는 `index.html`을 두어 **링크를 열면 덱이 바로 뜨게** 하고, `.nojekyll`을 둔다(`_src/` 같은 밑줄 폴더가 빠지지 않게).
- 덱 마지막 장에서 자료조사(`research/`)·분석 보고서(`report.md`)를 저장소 문서로 링크한다.
- 배포 뒤 공개 URL을 브라우저로 열어 쪽 수·글꼴·차트가 실제로 뜨는지 확인하고, URL을 프로젝트 README 첫 표에 남긴다.
- 로컬 원본을 고쳐도 공개 저장소는 저절로 바뀌지 않는다. 다시 올릴 때도 force push하지 않는다.
