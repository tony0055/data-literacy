# 데이터 → 분석 → 인사이트 → 전달 워크플로우

"이 데이터 분석하고 싶어", "시각화자료 만들어줘", "발표슬라이드 만들어줘"는 여기서 시작한다. 요청 범위까지만 단계를 밟는다. 방법 결정표는 [method-selector](../school/school_project/course-domain/method-selector.md), 개념·원문 근거는 [concepts](../school/school_project/course-domain/concepts.md), 과제·시험·팀 기준은 [assessments](../school/school_project/course-domain/assessments.md), 덱은 [data-to-slides-workflow](data-to-slides-workflow.md)가 소유한다.

## 0. 범위 정하기

| 요청 | 모드 | 끝나는 곳 |
| --- | --- | --- |
| 데이터 분석 | `analysis` | 단계 1–6, `report.md` |
| 시각화 자료 | `visualization` | 단계 1–4 중 차트에 필요한 집계 + 단계 7 |
| 발표 슬라이드 | `slides` | 검증된 분석(없으면 1–7) + 단계 8 |
| 실습 과제 | `practice` | 해당 주차 공지·명세의 요구 산출물 |
| 중간고사 대비 | `midterm` | 2–7주 통합 연습, 독립 채점 근거 |
| 기말 팀 프로젝트 | `team` | 9항목 계획 → 분석 → 민감도 → 덱 → 질의 준비 |

분석 요청에 덱·배포를 붙이지 않는다. 최신 요청이 형식·범위를 좁히면 해당하지 않는 단계·파일은 이유를 남기고 뺀다. 작은 수정은 기존 명세·로그를 참조하고 바뀐 부분만 다시 검증한다. `python3 scripts/course_workflow.py <모드> <모델>`은 읽을 문서·단계·산출물 계약을 JSON으로 출력한다(모델 호출·분석 완료가 아니다).

새 프로젝트는 `school/school_project/weekN/<project>/`. README에 목표·입력·실행법·산출물·검증을 남긴다.

## 1–8. 단계

| 단계 | 할 일 | 도구 | 산출물 | 통과 조건 |
| --- | --- | --- | --- | --- |
| 1. 질문 | 판단 주체·질문·조작적 정의·한 행의 의미·모집단/표본·기간·척도를 정하고 4칸 명세 | method-selector §3 | `spec.md` | 이미 정해진 것을 다시 묻지 않음; 미정 중 결과를 바꾸는 것만 질문 |
| 2. 확보 | 실제 파일·행·열·기간·이용 조건 확인. 없으면 결과를 만들지 않고 막힌 지점을 보고 | 공공데이터(data.go.kr·KOSIS 등) 직접 다운로드, 정해진 사이트 반복 수집은 Firecrawl, 일반 조사·로그인 페이지는 `ego-browser`, PDF·HWP는 `kordoc` | `sources.csv`(URL·기관·수집일·단위·행 수·기간·조건·해시) | 함정 #1·#11 통과 |
| 3. 진단 | 원본 보존, 파싱 기준 레코드 수, 자료형·결측 실제 표기·고유값·키·완전 중복·인코딩·단위·극단값 | Python(pandas) 또는 DuckDB/Polars | `diagnosis.json` | 처리 전에 진단만 |
| 4. 정제 | 명세에서 허용한 처리만 정제본에 실행 | 같은 코드 | `cleaning-log.csv`(무엇·왜·어떻게·영향 행·전후 행 수, 유지 결정 포함) | 함정 #2; 결과가 마음에 안 든다고 규칙을 사후 변경하지 않음 |
| 5. 분석 | 질문 유형에 맞는 방법을 method-selector에서 고르고 "함께 보고" 칸을 모두 계산 | `analysis.py`(고정 시드, 입력 버전) | 결과 표·수치 | 핵심 집계를 **손계산 또는 다른 집계 경로**로 대조 |
| 6. 인사이트 | 결론을 문장 등급으로 쓰고, 민감도(유지/삭제/대치, z/IQR, 전체/집단, 기간)로 견고성을 보고, 외부 맥락을 조사해 해석을 보강 | 공식 원출처 조사(`ego-browser`, Firecrawl) | `report.md`, `claims.csv`(주장·등급·근거 파일/표·출처·확인 상태) | 주장마다 근거 연결; "이 데이터로 주장할 수 없는 것" 명시 |
| 7. 시각화 | 차트마다 질문·단위·집계·분모·n을 정하고 검증된 집계만 그림 | 정적 그림은 matplotlib → SVG+PNG, 덱 안 차트는 `chart-data.json`을 읽는 SVG | `chart-data.csv/json`, `figures/`, `chart-notes.md` | 점검 4문(축 시작·단위·정렬·n) + 제목·출처·기준일; 렌더 파일을 직접 봄 |
| 8. 전달 | 덱·대본 | [data-to-slides-workflow](data-to-slides-workflow.md) | `presentation/`, `speaker-notes.md` | 전 장 실제 렌더 확인 |

### 단계 5–6 기준

- 평균·중앙값·SD·n·분모·단위·ddof를 함께 보고한다. z는 기준 집단과 분포, IQR은 양쪽 울타리와 사분위수 방법을 기록한다. 후보를 정답 이상치로 부르지 않는다.
- 상관은 r·n·산점도·결측·이상치 민감도·집단별 결과가 한 묶음이다. 인과 표현은 설계·교란 근거가 있을 때만.
- A/B는 사전 가설·배정 단위와 방식·대상·처치·지표·기간·표본·중단 규칙을 기록하고 효과·CI·검정 횟수, 탐색/확증을 구분한다.
- 차트가 분석 코드 출력과 같다는 검사는 **전달 경로**만 검증한다. 수치 정확성은 원본 손계산 또는 독립 집계로 확인한다. 평가 정답·허용 오차를 결과에 맞춰 바꾸지 않는다.
- 인사이트는 "숫자 → 그래서 무엇이 달라지나"다. 판단 주체가 할 수 있는 행동, 그 근거의 등급, 남은 불확실성을 한 문장씩 쓴다. 외부 자료는 원출처·날짜를 붙이고 이번 데이터의 결과와 구분한다.
- 주장이 많으면 주장별 확인(한 주장에 한 번의 독립 점검)을 하고, 확인 못 한 것은 "어디를 봤고 못 찾았다"로 남긴다.

### 단계 7 기준

- 값 비교는 막대, 시간은 선, 분포는 히스토그램/상자그림, 관계는 산점도, 구성은 누적막대. 선택 이유를 남긴다.
- 막대 값 축은 0 시작. 비영점 축이 필요한 다른 차트는 목적·범위를 공개한다. 정직/왜곡 비교 과제는 원본 값 동일성을 확인하고 왜곡 기법을 명시해 최종 차트와 분리한다.
- 강조색 1개 + 중립색, 색 외 모양·위치로도 구분. 구간 폭·색 범위·분모를 바꿔 결론이 바뀌는지 본다.
- 생성 이미지가 데이터 차트를 대신하지 않는다.

## 과제·시험·팀 특수 조건

주차 과제는 [assessments](../school/school_project/course-domain/assessments.md)와 원문을 읽고 그 조건을 일반 기본값보다 우선한다(4주 기본색·20구간·제출물 없음, 5주 비교표·판단 3줄·히스토그램 2장, 6주 같은 값 차트 쌍). 7–16주는 계획안이다. 확정/계획/확인 필요 상태를 산출물에 유지하고, 학교 공지가 오면 그것을 따른다.

## 위임과 기록

누구에게 무엇을 맡기는지는 [Routing](../harness/routing.md)이 정한다 — 자료 찾기·반복 집계는 싼 자리로, 분석 판단·통합·최종 확인은 메인 세션이, 핵심 수치 검산은 다른 계열이 한다. 실제로 쓴 제공자·모델·effort 지원 여부·담당 범위·수락/기각은 수업 제출물이면 `ai-use.csv`에 남긴다. 지원하지 않는 설정을 했다고 쓰지 않는다.

## 종료

요청한 산출물이 실제로 실행·열람되고, 명세·수치·차트·주장 검증이 끝나면 끝낸다. 저장소 검사는 사용자가 청할 때 돌린다. 분석만은 보고서, 시각화만은 렌더된 차트, 발표는 전 장 브라우저 확인이 완료 기준이다. 제출·외부 배포는 별도 허가를 따른다.
