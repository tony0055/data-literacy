# Routing · OmO에서 누가 어떤 일을 맡나

이 저장소의 기본 실행 환경은 OmO다. 배정은 모델 이름이 아니라 OmO의 **카테고리·에이전트**를 고르는 일이고, 그 뒤의 모델 사슬은 전역 `~/.omo/omo.jsonc`가 정한다 — 이 저장소에서 바꾸지 않는다(사슬을 고른 이유와 되돌리기는 그 파일의 주석이 가리킨다). 사용자가 모델·effort·실행 환경을 직접 지정하면 그대로 따른다. Fable·fast mode는 사용량 과금이 될 수 있어 사용자가 지정할 때만 쓴다.

## 원칙

1. **만드는 쪽과 검증하는 쪽을 가른다.** 만드는 쪽은 Claude, 검증하는 쪽은 GPT다. 같은 맥락에서 역할만 바꾼 검토는 검증이 아니다.
2. **검증은 틀리면 비싼 곳에만 붙인다** — 제출할 핵심 수치·결론 문장, 공개 배포, 하네스 변경.
3. **쪼갤 수 있는 양은 싼 자리로.** 자료원 찾기·원문 전사·반복 집계는 나누고, 한 덩어리 판단(질문 설계·방법 선택·결론 등급·덱 흐름)은 나누지 않는다.
4. **「다 했다」는 증거로 받는다** — 집계는 독립 재계산, 차트·덱은 렌더 PNG, 하네스는 `python3 scripts/checks`.

## 이 저장소의 일 → OmO 자리

| 이런 일 | 맡기는 곳 | 받을 것 |
| --- | --- | --- |
| 저장소·강의 자료 찾기, 파일 목록, 정해진 명령 실행, 값 뽑기 | `explore` · `quick` | 결과를 바로 확인할 수 있는 일만 — 경로·종료 코드·원문 인용 |
| 공개 통계·논문 찾기, 표 전사, 수집 스크립트 실행 | `librarian` · `unspecified-low` | 값마다 출처 URL·연령 구간·기준연도·직접/2차인용 |
| 분석 설계·방법 선택·인사이트 문장·덱 구성과 문안 | 메인 세션 또는 `unspecified-high` · `writing` | 결론 등급은 메인 세션이 정한다 |
| 차트·덱 화면·모션 구현 | `visual-engineering` | 전 장 렌더와 넘침 검사 결과 |
| 핵심 수치 독립 재계산, 주장 대장 검토 | `deep-low` | 만든 작업자와 다른 계열·다른 맥락에서 |
| 큰 계획 검토(팀 프로젝트·기말) | `plan-reviewer`(`/ulw-plan` 뒤) | 막는 지적과 메모를 나눠서 |
| 사용자와 주고받는 판단, 제출·배포·커밋 | 메인 세션 | 맡기지 않는다 |

## 나누는 법

| 상황 | 쓰는 것 |
| --- | --- |
| 한 파일·바로 확인되는 작은 일 | 그냥 한다 |
| 조사 → 분석 → 덱처럼 길고 맥락이 많다 | `ulw` |
| 검토된 계획이 먼저 필요하다 | `/ulw-plan` → 사용자 승인 → `/ulw-execute` |
| 끝날 때까지 도는 목표 | `/ulw-loop` |

- 맡기는 글의 첫 줄은 `TASK:`이고 `DELIVERABLE` · `SCOPE`(건드리지 말 것 포함) · `VERIFY` · `STOP WHEN`을 적는다. 증거로 못 가르는 결정을 만나면 추측하지 말고 첫 줄 `ESCALATE:`로 돌려달라고 적는다.
- 대상 하나에 작업자 하나. 고칠 파일이 겹치면 쪼개지 않는다. 조사하는 작업자는 고치지 않고, 쓴 작업자는 자기 결과를 검토하지 않는다.
- 작업자는 제출·배포·커밋·유료 생성·`school/school_materials/` 수정을 하지 않는다.
- 독립 자료원이 여럿이거나 수치 검산이 필요하면 먼저 한 줄로 제안한다 — 방식·작업자 수·얻는 것.

## OmO가 아닐 때

Claude Code와 Codex는 각자의 기본 하위 에이전트를 쓴다. 원칙과 경계는 같다.
